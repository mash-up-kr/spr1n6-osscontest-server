# 코드 컨벤션

## 이 문서의 목적

이 프로젝트는 API 서버, 릴레이, 워커, 검색 등 여러 파트를 각자 구현했다. 파트마다 언어와 프레임워크가 다르지만, **읽는 사람은 하나의 프로젝트로 읽는다.** 파트마다 코드를 읽는 방식이 달라지면 전체가 흩어져 보인다.

그래서 이 문서는 프레임워크 규칙이 아니라 **어느 파트에서나 지킬 수 있는 기준**만 담는다. 판단 기준은 세 가지다.

| 기준 | 묻는 것 |
| --- | --- |
| 가독성 | 처음 읽는 사람이 이 코드가 무엇을 하는지 바로 아는가 |
| 주석의 활용도 | 코드만으로 알 수 없는 것이 주석에 있는가, 없어도 되는 주석이 없는가 |
| 구조의 합리성 | 이 코드가 여기 있는 것이 당연한가, 경계가 분명한가 |

각 항목은 "지켜라"가 아니라 **확인할 수 있는 형태**로 적었다. 판단이 갈리면 이 문서가 기준이다.

---

# 1. 주석

가장 중요한 항목이다. 주석은 많을수록 좋은 것도, 적을수록 좋은 것도 아니다. **코드가 말할 수 없는 것만** 담겨 있어야 한다.

## 판단 규칙

주석은 세 가지 역할을 한다. 셋 중 어느 것도 아니면 지운다.

| 역할 | 붙는 자리 | 길이 |
| --- | --- | --- |
| 길잡이 | 흐름이 긴 함수의 각 단계 | 한 줄 요약 |
| 계약 | 공개 함수·클래스의 머리 | 두세 줄 |
| 근거 | 판단이 들어간 코드 바로 위 | 한두 문장 |

"주석을 줄인다"는 뜻이 아니다. **길잡이와 계약은 적극적으로 쓴다.** 지우는 대상은 코드 한 줄을 그대로 번역한 주석이다.

## 길잡이 주석

여러 줄로 된 흐름을 단계로 끊어 준다. 코드를 읽기 전에 뼈대를 먼저 보여 주는 역할이다.

- `~조회`, `~검증`, `~저장`, `~처리` 같은 **요약형 명사구**로 짧게 쓴다
- 한 줄 위에 그 줄을 번역해 붙이면 지울 대상이 된다
- 흐름이 짧고 이름만으로 읽히면 붙이지 않는다

```
// 업로드 권한 검증
...세 줄...

// 버전 번호 채번 및 저장
...다섯 줄...
```

## 계약 주석

공개 함수와 클래스에는 **호출하는 쪽이 알아야 할 것**을 적는다. 무엇을 하는지 한 줄, 그 뒤에 호출자가 지켜야 할 조건이나 주의할 점을 적는다.

- 이름만으로 충분한 것을 다시 쓰지 않는다
- 매개변수를 나열하는 대신, 이름으로 드러나지 않는 제약을 적는다
- 이 함수가 무엇을 보장하고 무엇을 보장하지 않는지 적는다

```
/**
 * 발행할 차례가 된 행을 최대 [limit] 건 집어 "내가 맡는다"고 표시하고 돌려준다.
 *
 * 고르는 것과 표시하는 것이 한 문장이라 그 사이에 다른 인스턴스가 끼어들 틈이 없다.
 */
```

## 근거 주석

판단이 들어간 자리에는 그 판단의 이유를 남긴다. 다섯 가지가 여기 해당한다.

**① 선택의 근거** — 왜 이 방법을 골랐는지

```
// 고르는 것과 표시하는 것을 한 문장으로 묶었다. 나누면 그 사이에 다른 인스턴스가
// 같은 행을 집을 수 있다.
```

**② 버린 선택지** — 왜 더 쉬워 보이는 방법을 안 썼는지

```
// 트랜잭션으로 묶지 않는다. DB 트랜잭션과 함께 커밋되는 것도 아니어서 얻는 것에 비해
// 비용이 크다.
```

**③ 값의 근거** — 숫자가 왜 그 숫자인지

```
// 여유 10초는 커넥션 타임아웃 5초에 안전 마진을 얹은 값이다. 30초로 두면 시연 설정과
// 산술적으로 양립할 수 없다.
```

**④ 밖에서 온 제약** — 우리가 정하지 않은 사정

```
// 이 컬럼의 스키마는 API 서버가 소유한다. 여기서는 맞는지 확인만 하고 고치지 않는다.
```

**⑤ 함정** — 코드를 그대로 읽으면 오해하게 되는 지점

```
// getLong 은 SQL NULL 에 예외를 내지 않고 0 을 돌려준다. wasNull 을 함께 확인해야 한다.
```

## 지울 주석

- **코드 한 줄을 그대로 옮긴 것.** `findByUserId(userId)` 위의 `// 사용자 ID로 조회한다`
- **주석 처리된 코드.** 이력은 git 에 남는다
- **주인도 기한도 없는 TODO/FIXME.** 남기려면 무엇을·왜·언제까지인지 적는다
- **자동 생성 템플릿.** `@param` 만 나열하고 설명이 없는 문서 주석
- **변경 이력.** `// 2026-08-12 수정`
- **구분선 장식.** `// ===== 여기부터 조회 =====`

## 고칠 주석

- **코드와 어긋난 주석.** 가장 위험하다. 읽는 사람을 틀린 방향으로 보낸다. 발견 즉시 고치거나 지운다
- **너무 긴 주석.** 핵심 한두 문장으로 줄인다. 배경 설명이 길어야 하면 문서로 옮기고 링크한다
- **여러 판단을 한 덩어리에 몰아 쓴 주석.** 해당 코드 옆으로 나눠 붙인다

## 문체

파트가 여러 개라 문체가 갈리면 한 프로젝트로 읽히지 않는다. 아래로 통일한다.

- **평서형 단정체로 쓴다.** 문장을 `~한다`, `~하지 않는다`, `~여야 한다` 로 끝낸다. 존댓말(`~합니다`)과 반말 구어체를 쓰지 않는다
- **길잡이 주석은 요약형 명사구로 쓴다.** `~조회`, `~검증`, `~저장`
- **추측과 완곡 표현을 쓰지 않는다.** `~할 수도 있다`, `~하는 게 좋을 것 같다` 대신 단정해서 적는다. 확실하지 않으면 확인한 뒤에 적는다
- **감정과 사과를 넣지 않는다.** `안타깝게도`, `어쩔 수 없이`
- 한글로 쓴다. 고유명사와 API 이름은 원문 그대로 둔다
- 공개 함수·클래스의 설명은 그 언어의 문서 주석(`/** */`, `"""docstring"""`)을 쓴다

```
// 좋음
// 이 값보다 짧으면 진행 중인 배치가 끝나기 전에 종료된다.

// 나쁨 — 완곡, 구어체
// 이 값은 좀 넉넉하게 잡는 게 좋을 것 같습니다.
```

# 2. 가독성

## 이름

- 이름이 **역할**을 말하게 한다. 타입이나 자료구조를 이름에 넣지 않는다 (`userList` → `users`, `dataMap` → `versionsByDocument`)
- 줄임말을 만들지 않는다. 프로젝트에서 이미 쓰는 줄임말만 쓴다
- 불리언은 참일 때의 상태를 말한다 (`deleted`, `hasNext`, `canRetry`)
- 함수 이름에 동사를 쓰고, 그 동사가 실제 행위와 맞는지 확인한다. 조회 함수가 값을 바꾸거나, `update`가 새로 만들면 이름이 거짓말을 하는 것이다
- **같은 개념은 프로젝트 전체에서 같은 이름으로 부른다.** 파트마다 다르게 부르면 전체가 흩어져 보인다. 아래 용어를 기준으로 한다

| 개념 | 쓰는 이름 | 쓰지 않는 이름 |
| --- | --- | --- |
| 문서 식별자 | `documentId` | `docId`, `document_no` |
| 문서 버전 번호 | `versionNo` | `version`, `versionNumber` |
| 문서 버전 식별자 | `documentVersionId` | `versionId` |
| 이벤트 식별자 | `eventId` | `messageId` |
| 테넌트 식별자 | `tenantId` | `orgId` |
| 추적 식별자 | `traceId` | `requestId` |

새 공통 개념이 생기면 이 표에 추가하고 파트끼리 맞춘다.

## 함수

- 함수 하나가 한 가지 일을 한다. "그리고"로 설명해야 하면 나눌 자리다
- 한 함수 안에서 **추상화 수준을 맞춘다.** 업무 흐름을 설명하는 줄과 바이트를 자르는 줄이 같은 함수에 섞이지 않게 한다
- 중첩은 얕게 둔다. 예외 상황을 먼저 처리하고 빠져나가면(early return) 본문이 평평해진다
- 매개변수가 많아지면 묶는다. 특히 같은 타입이 연달아 오면 호출부에서 순서를 틀리기 쉽다
- 공개 범위를 최소로 둔다. 밖에서 독립적으로 쓸 수 있는 것만 공개한다

## 값

- 매직 넘버를 코드에 박지 않는다. 이름 있는 상수나 설정으로 뺀다
- 시간, 크기, 횟수 같은 운영 값은 설정으로 뺀다. 기본값을 주고 근거를 주석으로 남긴다
- 하드코딩된 주소·경로·자격증명을 코드에 두지 않는다. 환경변수로 받는다

## 지울 것

- 쓰이지 않는 함수, 클래스, 변수, import
- 도달할 수 없는 분기
- 실험하다 남은 코드
- 이름만 다르고 하는 일이 같은 함수

읽는 사람은 코드가 있으면 이유가 있다고 가정한다. 안 쓰는 코드를 남기면 그 가정이 깨진다.

# 3. 구조

## 경계

- **내 파트가 소유한 것과 남의 것을 구분한다.** 남이 소유한 스키마·계약·데이터를 내 파트에서 고치지 않는다. 맞는지 확인만 하고, 어긋나면 드러나게 한다
- 파트 간 계약(이벤트 형식, API 응답, DB 스키마)을 바꾸면 상대 파트와 맞춘 뒤에 올린다
- 계약에 기대는 코드에는 **누가 그 계약을 소유하는지** 주석으로 남긴다

## 배치

- 파일은 기능 단위로 먼저 묶고, 그 안에서 역할로 나눈다
- 한 파일이 여러 관심사를 담기 시작하면 나눌 자리다
- 여러 파트가 공유하는 개념은 공용 위치에 두고, 한 곳에서만 쓰는 것은 그 자리에 둔다
- 의존 방향을 한쪽으로 유지한다. 서로를 부르는 관계가 생기면 구조가 잘못된 것이다

## 계층

파트마다 이름은 달라도 역할은 같다.

| 역할 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 입출력 | 요청·메시지를 받아 형식을 확인하고 넘긴다 | 업무 판단, 저장 |
| 업무 | 흐름을 정하고 규칙을 확인하고 상태를 바꾼다 | 입출력 형식 처리 |
| 저장 | 읽고 쓴다 | 업무 판단 |

- 입출력 계층에 업무 판단이 들어가면 옮긴다
- 업무 계층이 요청 형식을 알아야 하면 경계가 잘못 그어진 것이다
- 저장 계층이 업무 규칙을 판단하면 옮긴다

## 중복

- 같은 로직이 세 번째 나타나면 묶는다. 두 번까지는 그대로 둔다
- 우연히 같아 보이는 코드를 억지로 묶지 않는다. 함께 바뀔 것만 묶는다

# 4. 실패 처리

읽는 사람이 "이 코드는 실패하면 어떻게 되는가"를 알 수 있어야 한다.

- 외부 경계(DB, HTTP, 메시지 브로커, 파일)에서 **빈 값과 기본값을 구분한다.** 없는 값이 `0`이나 빈 문자열로 둔갑하지 않게 한다
- **조용히 틀리지 않게 한다.** 오류도 로그도 없이 잘못된 값이 흘러가는 코드가 가장 나쁘다
- 조건이 어긋났을 때 오류 대신 "결과 0건"으로 끝나는 경로를 경계한다. 0건은 오류로 보이지 않는다
- 예외를 잡아서 삼키지 않는다. 삼켜야 한다면 왜 삼켜도 되는지 주석으로 남긴다
- 잘못된 설정으로 도느니 **시작을 막는다**
- 로그와 오류 메시지에 민감 정보나 요청 본문 전체를 넣지 않는다

---

# 5. 테스트

- 테스트 이름은 **상황과 기대 결과**를 말한다. `~를 호출한다` 같은 구현 표현을 쓰지 않는다
- 이름만으로 부족하면 "이 단언이 깨지면 무엇이 잘못된 것인지"를 주석으로 남긴다
- 결함을 고쳤으면 **수정을 되돌렸을 때 그 테스트가 실제로 실패하는지** 확인한다. 확인하지 않은 테스트는 회귀를 막지 못한다
- 공유 자원의 설정을 바꾸는 테스트는 전용 자원을 만들어 다른 테스트에 영향을 주지 않게 한다
- 실패가 간헐적인 테스트는 원인을 단정하기 전에 변경 전후를 같은 횟수로 돌려 비교한다

---

# 6. 커밋과 PR

- 커밋 메시지는 `{type}: {한글 요약}` 형식을 쓴다 (`feat`, `fix`, `docs`, `chore`, `refactor`)
- 요약은 무엇을 고쳤는지보다 **무엇이 문제였는지**가 드러나게 쓴다
- 원인이 다른 수정은 커밋과 PR 을 나눈다. 서로 없으면 안 되는 변경만 한 커밋에 묶는다
- 정리(주석·이름·죽은 코드) 커밋과 동작을 바꾸는 커밋을 섞지 않는다. 섞이면 리뷰가 불가능해진다
- PR 본문에는 무엇이 문제였는지, 어떻게 재현되는지, 무엇을 고쳤는지, 어떻게 검증했는지를 적는다

# 제출 전 체크리스트

각 파트 담당자가 자기 파트에 대해 확인한다.

**주석**

- [ ] 코드를 그대로 옮긴 주석을 지웠다
- [ ] 주석 처리된 코드를 지웠다
- [ ] 코드와 어긋난 주석이 없다
- [ ] 숫자(타임아웃·상한·크기)에 근거가 적혀 있다
- [ ] 파트 간 계약에 기대는 코드에 소유자가 적혀 있다

**가독성**

- [ ] 이름이 역할을 말한다
- [ ] 공통 개념을 용어표대로 부른다
- [ ] 안 쓰는 코드와 import 를 지웠다
- [ ] 매직 넘버를 상수나 설정으로 뺐다
- [ ] 하드코딩된 주소·자격증명이 없다

**구조**

- [ ] 계층 역할이 섞이지 않았다
- [ ] 남이 소유한 것을 내 파트에서 고치지 않았다
- [ ] 서로 부르는 의존이 없다

**실패**

- [ ] 조용히 틀리는 경로가 없다
- [ ] 삼킨 예외에 이유가 적혀 있다

**테스트**

- [ ] 테스트 이름이 시나리오와 기대 결과를 말한다
- [ ] 결함 수정에 딸린 테스트가 회귀를 실제로 잡는다
